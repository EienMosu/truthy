## 3. Changes between 15 and 16 (and 14 to 15): pin cards to a version
Verified quotes:
- 14 to 15 (v15 guide): "`fetch` requests are no longer cached by default." Opt in with `cache: 'force-cache'`. "`GET` functions in Route Handlers are no longer cached by default" (opt in via `dynamic = 'force-static'`). Client Cache: "page segments are no longer reused from the Client Cache" on Link/useRouter navigation, still reused on back/forward and shared layouts; opt in with `staleTimes`. Also `cookies`, `headers`, `draftMode`, `params`, `searchParams` became async (sync access temporarily allowed).
- 15 to 16 (v16 guide): "synchronous access is fully removed" for those async request APIs. `experimental.ppr` and `experimental_ppr` removed; "you can opt into PPR using the `cacheComponents` configuration"; "PPR in Next.js 16 works differently than in Next.js 15 canaries". `experimental.dynamicIO` renamed `cacheComponents`; `experimental.useCache` removed. `revalidateTag(tag)` single-arg deprecated; now `revalidateTag('posts', 'max')`. New: `updateTag` (Server Actions only, read-your-writes), `refresh`. `cacheLife` and `cacheTag` stable (no `unstable_` prefix). `middleware` renamed `proxy` (Node.js runtime). Turbopack default bundler. Prefetching rewritten (layout deduplication, incremental prefetching).
- 16.0 blog: "caching with Cache Components is entirely opt-in. All dynamic code in any page, layout, or API route is executed at request time by default."
- Caching page (16.3.8): Cache Components "is enabled by setting `cacheComponents: true`"; PPR is "the default behavior with Cache Components"; `<Suspense>` "does not itself opt a component into dynamic rendering"; direct quote: "Reading `cookies()` here doesn't opt-in the whole route into dynamic rendering, the way the previous rendering model did."
- Previous model page: default `dynamic = 'auto'`, `revalidate = false`; "By default, `fetch` requests are not cached."
- 16.3 additions (all opt-in via flags `cacheComponents` + `partialPrefetching`): Instant Navigations, Partial Prefetching, "Better ISR" (first visitor to a non-prerendered URL gets a loading shell, upgraded in background), `catchError`, root params (`next/root-params`). Blog: "The behaviors behind Instant Navigations will become the default in a future major version."
Version-pinning rule: any card on fetch/route handler/router-cache defaults, revalidateTag signature, PPR flag, or the meaning of "dynamic by default" must state "Next.js 14", "15", or "16 (Cache Components on/off)".

## 4. Proposed sections (8), about 12 true/false facts each
1. Server vs Client Components (stable). Pages: server-and-client-components, server-and-client-boundary, use-client, react.dev Server Components. Facts: layouts/pages are Server Components by default; use client marks a module-graph boundary; context not supported in Server Components; props must be serializable; server-only package optional; NEXT_PUBLIC_ prefix rule; Server Components passed as children are not pulled into the client bundle.
2. How a request renders: RSC Payload, HTML, hydration (stable). Page: server-and-client-components ("On the server", "On the client (first load)", "Subsequent Navigations"). Facts: RSC Payload contents; HTML is non-interactive preview; hydration attaches event handlers; Client Components on later navigations render without server HTML; Preventing Flash guide. Risk of thinness: add react.dev hydrateRoot/hydration-mismatch facts (not yet fetched).
3. Streaming and Suspense (mostly stable). Pages: streaming guide, loading.js, Caching page "Streaming uncached data". Facts: Suspense fallback ships in the shell; Suspense does not itself make a component dynamic; bots/crawlers get full dynamic render (16.x). Need first-hand read of the Streaming guide.
4. Static vs dynamic rendering and the Pages Router equivalents (stable core, version-pinned). Pages: Pages Router rendering pages, getStaticProps/getServerSideProps/getStaticPaths, Automatic Static Optimization, Rendering Philosophy. Facts: SSG at build, SSR per request, ASO, request-time APIs make a route dynamic in the old model. Needs first-hand read of Pages Router pages.
5. Data fetching patterns (stable). Pages: fetching-data, client-side-data-fetching, React cache dedupe, preload pattern, fetch memoization. Facts: fetch memoized within a render pass; React cache for non-fetch; parallel vs sequential; client-side with SWR/TanStack Query.
6. Caching defaults and the previous model (version-pinned, high value). Pages: v15 guide, caching-without-cache-components, fetch reference, unstable_cache. Facts: 14 to 15 default flips; force-cache; dynamic/revalidate/fetchCache segment config values; lowest revalidate wins across segments; dev pages never cached.
7. Cache Components, use cache and PPR (16-only, pin to 16.x). Pages: Caching, cacheComponents, use-cache, cacheLife, cacheTag, use cache private/remote, Migrating. Facts: opt-in flag; cache key includes args and captured values and build id; implicit default cacheLife profile; static shell composition; connection() for per-request random; remote vs in-memory store. Slightly volatile: restrict to concepts stated on the Caching page, avoid numeric cacheLife profile values until fetched.
8. Revalidation, ISR and Server Actions (mixed). Pages: revalidating, how-revalidation-works, ISR guides, revalidatePath/Tag, updateTag, refresh, mutating-data, server-actions guide, use server. Facts: revalidateTag 2-arg (16), updateTag Server-Actions only, refresh() refreshes uncached data only, Server Actions are Server Functions used for mutations, ISR on-demand vs time-based.

Too volatile or too thin to be their own section:
- Instant Navigations / Partial Prefetching / ISR with Cache Components (new in 16.3, opt-in, flags, "will become default in a future major version"): fold at most 1 to 2 facts into section 7; no standalone section.
- Turbopack, React Compiler, proxy.ts, image defaults, Build Adapters, glob imports, offline support: out of scope for rendering, churn each minor.
- Hydration as its own section: thin in Next docs (one definition box); merged into section 2 with react.dev material.
- Edge vs Node runtime for rendering: docs in flux (proxy is Node only, middleware edge deprecated).
- Numeric facts (cacheLife profile durations, staleTimes numbers, performance percentages): avoid or pin to 16.3.x.
