- Variable and expression traps (https://learn.microsoft.com/en-us/azure/devops/pipelines/process/variables?view=azure-devops): template expressions ${{ }} are processed at compile time, can appear as keys or values and coalesce to an empty string; macro syntax $( ) is processed at runtime just before a task runs, is expanded only for values in task inputs (not in compile-time keywords such as resources, trigger or a checkout repository reference) and prints as literal $(var) when the variable does not exist; runtime expressions $[ ] are processed at runtime, must take the whole right side of a key-value pair and coalesce to an empty string. A variable set in the YAML variables block cannot be overridden at queue time. Secret variables are not mapped to environment variables automatically and must be mapped explicitly; Microsoft says not to set secret variables in the YAML file; by default, pull request builds from forks of a GitHub repository do not get the pipeline's secrets.
- Template traps (https://learn.microsoft.com/en-us/azure/devops/pipelines/process/templates?view=azure-devops): includes templates insert content, extends templates define what a pipeline may contain and pair with the required template check; template files must exist when the run starts (not in an artifact); repository resources for templates are resolved once at the start of the run and only template files are used, so scripts in the template repository are not available; untyped template parameters are treated as strings. Approvals and checks are not defined in the YAML file: the owner or administrator of the protected resource (environment, service connection, agent pool, repository, variable group, secure file) manages them; checks run in five categories, static checks (branch control, required template, evaluate artifact) first, then pre-check approvals, dynamic checks, post-check approvals and finally exclusive lock, whose lockBehavior (runLatest by default, or sequential) is set in YAML (https://learn.microsoft.com/en-us/azure/devops/pipelines/process/approvals?view=azure-devops).
