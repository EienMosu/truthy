RULES FOR THE STATEMENT
- Original wording. Do not copy or paraphrase practice exams, exam dumps or course material.
- One fact per statement. No compound statements where one half is true and the other false.
- Maximum 120 characters. Plain declarative sentence, present tense.
- No negations ("is not", "cannot", "never", "without") in the statement.
- No absolutes ("always", "all", "only", "every", "must") unless the official source states it that way.
- Use official product and API names exactly as the official source writes them today.
- A false statement is false for exactly one clear reason, and that reason is a realistic misconception a learner who studied could hold. Never make a statement false through trick wording, spelling or a changed number.
- No strawman: if nobody who studied would answer True, write a different card.
- No truism: a statement that is true by common sense, by definition or by arithmetic, and that is not specific to this subject, teaches nothing. Write a different card.
- No name giveaway: the answer must not be readable from the product name alone (for example "X for Windows File Server provides Windows file systems").
- True and false statements must be indistinguishable by form: within each section keep the average length of the false statements within 5 characters of the average length of the true ones, and use the same sentence patterns for both.
- No wording tells. A player who does not know the subject must not be able to guess from the words. Hedge verbs ("can", "supports", "lets", "allows", "may") must not mark true statements: use them about as often in false statements as in true ones. Requirement and coverage words ("requires", "must", "each", "every", "automatically", "by default", "directly") must not mark false statements: use them about as often in true statements as in false ones. - Permissions traps worth testing (each at most once in the deck): x on a directory is search permission and r only lists names; deleting a file depends on the directory's permissions, not the file's, unless the sticky bit is set; only the first matching class applies, so an owner with fewer rights than the group gets the owner's rights; umask removes bits from the requested mode, it does not set them, and a regular file is not created executable by umask alone; Linux ignores setuid and setgid on interpreter scripts (execve(2)); on a nosuid mount the bits give no privilege, but execve(2) says that, depending on the kernel version, the program either runs without them or is refused, so a card says only that the bits do not take effect; setgid on a directory makes new files inherit the directory's group; S and T in ls -l mean the special bit is set without the matching execute bit; chmod does not change the permissions of symbolic links; adding a user to a group does not change the groups of processes already running.
- Links traps: a hard link and its original are equal names for one inode (neither is the "original"); hard links cannot point to directories or cross filesystems (mounts), while symbolic links can do both and can dangle; a relative symlink target is resolved from the directory containing the link, not from the working directory where ln ran; mv within one filesystem renames without copying data, across filesystems it copies and deletes. The protected_symlinks and protected_hardlinks sysctls are documented on docs.kernel.org, which states no default; systemd's sysctl.d/50-default.conf sets both to 1, and a distribution can override it. Their effect may be tested; their value must not be stated as a kernel default or as a fact about every system.
- Signals and jobs traps: kill without a signal sends SIGTERM, not SIGKILL; SIGKILL and SIGSTOP cannot be caught, blocked or ignored, so SIGKILL gives no chance to clean up; an interactive Bash with no traps ignores SIGTERM; an interactive Bash that receives SIGHUP resends it to all its jobs, running or stopped, before exiting, but an interactive login shell sends SIGHUP to its jobs on a normal exit only when huponexit is set; nohup does not put a command in the background (it ignores SIGHUP and appends output to nohup.out when stdout is a terminal); disown removes a job from the shell's job table. Exit status 128+N after a fatal signal, 127 for command not found and 126 for found but not executable are Bash rules: cite the Bash manual.
- Shell traps: the shell, not the command, expands globs, so a pattern that matches nothing is passed on unchanged unless nullglob or failglob is set; * does not match names starting with a dot unless dotglob is set; brace expansion generates words whether or not files exist; single quotes prevent every expansion while double quotes allow $, backquote and backslash; unquoted variable expansions undergo word splitting and globbing; a child process cannot change its parent's environment, so a script that sets variables must be sourced to affect the current shell; export makes a variable part of the environment of later commands. Keep set -e to its documented exceptions (the Bash manual lists the commands after while, until, if and elif, all but the last command of a && or || list, all but the last command of a pipeline, and commands inverted with !) or leave it out; do not write a card claiming set -e stops on every failure.
- Redirection traps: redirections are processed left to right, so `cmd > file 2>&1` sends both streams to the file while `cmd 2>&1 > file` leaves errors on the terminal; a pipe carries only standard output unless |& or 2>&1 is used; a pipeline's status is the last command's unless pipefail is set; `sort file > file` truncates the file before sort reads it.
- Tool traps: grep -r follows symbolic links only when they are on the command line, -R follows all; GNU grep 3.8 and later make egrep and fgrep print an obsolescence warning (use grep -E and grep -F), and grep exits 1 when nothing matches and 2 on error (unless -q is used and a line matched); uniq removes only adjacent duplicates; sort order depends on the locale, and LC_ALL=C gives byte order; xargs splits on blanks and newlines, so file names with spaces need find -print0 with xargs -0; find -exec {} + runs few commands with many names while \; runs one per file; find -delete implies -depth and, placed before the tests, deletes everything under the starting points; GNU tar strips a leading / from member names unless -P is given; with OpenSSH, StrictHostKeyChecking defaults to ask, and accept-new adds unknown host keys but refuses changed ones; tail -F keeps following a file that is rotated or recreated, -f follows the open file descriptor.
- systemd traps: enable creates the symlinks from the [Install] section and reloads the manager configuration itself, but does not start the unit unless --now is given; disable does not stop a running unit unless --now is given; mask links a unit to /dev/null under /etc/systemd/system so it cannot be started at all, manually or as a dependency, which disable does not do; unit files in /etc/systemd/system override those of the same name in /usr/lib/systemd/system; after creating or editing unit files by hand, systemctl daemon-reload is needed, while systemctl edit, enable and disable reload for you; stopping a service sends KillSignal= (SIGTERM by default) and SIGKILL after the stop timeout. Targets replace SysV runlevels: write no card that presents runlevelN.target aliases, telinit or runlevel as available, since systemd 258 removed them (260 can restore the targets only through a build option). Leave out numeric defaults (timeouts, rate limits, journal size limits), cgroup internals, systemd-boot, systemd-homed, portable services, sysupdate and anything the man pages mark as added after the pinned release; check the "Added in version" lines and use the man pages under /software/systemd/man/latest/ (or the v262 man sources on GitHub).
