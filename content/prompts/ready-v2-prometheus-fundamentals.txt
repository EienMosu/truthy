DECK
Prometheus fundamentals for working operators: metrics, scraping, discovery and relabeling, PromQL, rules, Alertmanager, instrumentation, storage, remote write and federation.
Taxonomy: devops > Prometheus > topics > Fundamentals. This is a docs deck; official Prometheus documentation defines its scope, and the section grouping is this deck's own. Pin Prometheus 3.15.0, listed as Latest with release date 2026-09-24, and Alertmanager 0.34.1, listed as Latest with release date 2026-09-17, on https://prometheus.io/download/ when opened on 2026-10-08. Release confirmations: https://github.com/prometheus/prometheus/releases/tag/v3.15.0 and https://github.com/prometheus/alertmanager/releases/tag/v0.34.1. The audience runs Prometheus and interprets operational metrics; deployment recipes and managed cloud offerings are outside this deck.

Hedge verbs ("can", "supports", "lets", "allows", "may") must not mark true statements: use them about as often in false statements as in true ones. Requirement and coverage words ("requires", "must", "each", "every", "automatically", "by default", "directly") must not mark false statements: use them about as often in true statements as in false ones. - Difficulty mix within each section: roughly 40% easy (1), 40% medium (2), 20% hard (3). Hard means a real distinction between two similar things, not an obscure detail.
- Depth: a working operator who configures collection, writes useful queries and diagnoses missing data or unexpected alerts. Test observable behavior and configuration consequences. Short PromQL expressions and configuration names are welcome; avoid YAML indentation, installation commands, UI navigation, error-message trivia, histogram encoding internals and performance benchmarks.
- Assumed context: ordinary Prometheus server mode with default feature flags, using stored metrics of the stated type. Name the relevant configuration when it decides the answer. Distinguish classic from native histograms and counter from gauge histogram flavors; these are separate distinctions. Queries must make their input type, label relationships and time window clear enough to decide the result.
- Version pinning: use Prometheus 3.15.0 and Alertmanager 0.34.1. Put the product version in the statement when the answer depends on a changed default or release-specific behavior, and in appliesTo. Older release facts provide guardrails, not release-number trivia. The pins are confirmed by https://prometheus.io/download/ and the two release pages in STEP 1.
- Data-model trap: Prometheus 3 supports UTF-8 metric and label names, while the older ASCII patterns remain compatibility recommendations. Samples may contain native histograms as well as float values. Do not teach the older restrictions as universal current behavior. Ground this in https://prometheus.io/docs/concepts/data_model/. Naming guidance about base units, suffixes and _total is a recommendation, not a validation requirement; use https://prometheus.io/docs/practices/naming/.
- Native histogram trap: the specification says native histograms are stable since 3.8.0 and the native-histograms feature flag is a no-op since 3.9. In the pin, scrape_native_histograms defaults to false; activation is through configuration. The current classic-companion option is always_scrape_classic_histograms. Use https://prometheus.io/docs/specs/native_histograms/, https://prometheus.io/docs/prometheus/latest/migration/ and the pinned configuration reference. Include native histogram representation and querying in r3; activation belongs to r4. Exclude exposition-format exclusivity and client-library support matrices because the current prose and release notes have not been reconciled.
- Distribution traps: summary quantiles cannot be combined into a valid aggregate percentile, but observation sums and counts can be aggregated. Histogram quantiles are estimates; classic aggregation for histogram_quantile retains le, while native aggregation operates on composite samples. Standard exponential native buckets and NHCBs have different layout-reconciliation limits. Negative observations can make classic histogram or summary sums decrease. Use https://prometheus.io/docs/practices/histograms/ and https://prometheus.io/docs/prometheus/latest/querying/functions/. Keep representation and quantile facts in r3.
- PromQL traps: rate is an extrapolated average per-second counter rate; irate uses the last two samples; increase scales the rate over the window and may be noninteger. Compute rates before aggregation so resets remain detectable. Use https://prometheus.io/docs/prometheus/latest/querying/functions/. In Prometheus 3, range/lookback boundaries are left-open and right-closed, regex dot matches newlines, and @ and negative offsets need no old enabling flags; use https://prometheus.io/docs/prometheus/latest/migration/. A range query is repeated evaluation, not the range-vector expression type; use https://prometheus.io/docs/prometheus/latest/querying/basics/. Do not equate stale or missing data with zero.
- Collection traps: up=1 means the scrape succeeded, not that the application is healthy. Target relabeling precedes scraping; labels beginning with __ are removed from the final target label set, though their values may configure scraping. Metric relabeling runs before ingestion and excludes generated up. A compatible scrape fallback does not make malformed metric data valid. Use https://prometheus.io/docs/concepts/jobs_instances/ and https://prometheus.io/docs/prometheus/latest/configuration/configuration/.
- Instrumentation recommendations must be attributed to the Prometheus documentation. Test known-zero initialization, bounded dimensions, exporting event timestamps, and collecting exporter values during scrapes with documented caching qualifications. Pushgateway guidance is principally for service-level batch outcomes; pushed series persist until deleted. Use https://prometheus.io/docs/practices/instrumentation/, https://prometheus.io/docs/instrumenting/writing_exporters/ and https://prometheus.io/docs/practices/pushing/. Avoid claims that any exporter or push endpoint proves the originating service is healthy.
- Alerting boundaries: Prometheus rules determine alert instances and pending/firing state; Alertmanager handles notifications. Grouping, inhibition and silences do not change Prometheus rule evaluation. Routing depends on inherited settings and continue, not merely the presence of a matching receiver. The old match and match_re route fields are deprecated in favor of matchers; do not use them as current configuration. Use https://prometheus.io/docs/prometheus/latest/configuration/alerting_rules/, https://prometheus.io/docs/alerting/latest/alertmanager/ and https://prometheus.io/docs/alerting/latest/configuration/. Avoid matcher-parser default claims from transitional documentation.
- Storage traps: local TSDB storage is single-node, with no built-in clustered replication. When time and size retention both apply, the first triggering policy governs; expiration removes fully expired blocks in the background. Size retention is not a strict ceiling on total disk use. Remote write has WAL-backed buffering and retries, with finite outage tolerance rather than guaranteed unlimited delivery. Federation scrapes selected current series, not historical TSDB blocks. Use https://prometheus.io/docs/prometheus/latest/storage/, https://prometheus.io/docs/practices/remote_write/ and https://prometheus.io/docs/prometheus/latest/federation/.
- Remote native histogram sending depends on the protocol: the pinned configuration makes send_native_histograms false by default for remote write v1; with io.prometheus.write.v2.Request it is ignored and sending is enabled. This does not enable scraping or establish receiver support. Cite https://github.com/prometheus/prometheus/blob/v3.15.0/docs/configuration/configuration.md. Leave out experimental PromQL functions and modifiers, experimental concurrent rule evaluation, start-timestamp experiments and protocol wire details. The migration guide renames holt_winters to the experimental double_exponential_smoothing; exclude both from this fundamentals scope. Test settings rather than numeric scrape, lookback, retention, queue or notification defaults.

Cloud decks own managed monitoring offerings, including Amazon Managed Service for Prometheus and Google Cloud Managed Service for Prometheus. Docker, Linux, Terraform, Ansible and CI decks own deployment and automation; language decks own client-library syntax. Keep every card about upstream Prometheus behavior.
