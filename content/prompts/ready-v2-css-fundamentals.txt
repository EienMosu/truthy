Nesting changed in 2023 (relaxed syntax: & is no longer needed before a nested type selector) and in 2024 (declarations after nested rules keep their position instead of being hoisted): describe today's behaviour and cite Guides/Nesting/Using or the CSSNestedDeclarations page; never teach the older behaviour as current. :has() takes an unforgiving <relative-selector-list>: the Selectors 4 editor's draft (https://drafts.csswg.org/selectors-4/) says "<forgiving-selector-list> is used in :is() and :where() only"; cite that draft for a :has() parsing card, because MDN only says :has() fails unless it sits inside :is() or :where().
- Cascade traps, verified on MDN and Cascade 5: transition declarations beat important ones, and animation declarations beat normal declarations (including normal style attribute declarations) but not important ones, so never write that only !important can override an inline style (MDN's Specificity page says "The only way to override inline styles is by using !important" and models inline styles as a 1-0-0-0 weight: build no card on either sentence). For important declarations the origin order reverses (user-agent important beats user important beats author important) and the layer order reverses (the first declared layer wins, and layered important beats unlayered important). Layer order is fixed by the first time a layer name appears, not by where its rules are written. Specificity counts only within the same origin, importance and layer: a later layer beats an earlier one whatever their specificity. revert in author styles rolls back to the user or user-agent origin, so `display: revert` on a div gives block while `display: initial` gives inline. revert-layer rolls back to earlier layers and then to the previous origin; MDN's revert-layer page says that, unlike revert, it keeps presentational hints when used outside any layer, so write no card equating revert-layer with revert and none about presentational hints. @scope proximity is compared only after specificity (MDN @scope page; the Cascade 6 sorting criteria), even though a note in the 2024 Cascade 6 draft still says proximity applies "regardless of specificity": write no card claiming that proximity beats specificity. MDN's Specificity page calls the last-declared rule "the proximity rule": use "order of appearance" for that and "scope proximity" only for @scope.
- Specificity traps: the columns are compared one at a time and never carry over; :where() and the universal selector add zero; :is(), :not() and :has() add the weight of their most specific argument even when another argument matched; & in nesting weighs like :is() over the parent's whole selector list, which differs from what Sass produces; the specificity of & inside @scope differs by browser engine and release (MDN @scope page): no card on it. Inline styles are not part of selector specificity (Cascade 5 handles them as element-attached styles), so write "style attribute" cards as cascade facts in r1, not as specificity in r3; specificity of a rule does not pass to children, which receive only inherited values.
- Box and layout traps: box-sizing is not inherited and its initial value is content-box (do not test which form controls a browser's own style sheet sets to border-box); percentage padding and margin in all four directions resolve against the containing block's inline size (width here), never its height; margins collapse only in the block direction, never for floats, absolutely positioned boxes or children of flex and grid containers; overflow: clip does not create a block formatting context while overflow: hidden does; z-index has no effect on a non-positioned block box but works on flex and grid items without position; position: fixed and sticky always create a stacking context, absolute and relative only with a z-index other than auto; a sticky element needs at least one inset value other than auto on its axis (otherwise it behaves as relative) and sticks to its nearest ancestor with a scrolling mechanism (overflow hidden, scroll, auto or overlay) even if that ancestor does not actually scroll. For the containing block of fixed elements, cite the Containing_block guide and use transform as the example: the guide lists filter, backdrop-filter, transform, perspective, rotate, scale, translate, contain, will-change and content-visibility: auto and warns that perspective and filter behave inconsistently across browsers, so write no card that rests on perspective or filter. align-content also applies to block containers today (MDN's align-content page): write no card claiming it works only in flex or grid layouts, and no card on its block-layout behaviour.
- Query container trap: MDN lists container-type size and inline-size among the creators of a stacking context and of a block formatting context; CSS Conditional 5 says such containers apply style and size (or inline-size) containment and establish an independent formatting context, and says nothing about stacking contexts, while the old Containment 3 draft also applied layout containment. Write no card on whether a query container creates a stacking context, a block formatting context or a containing block for fixed elements, and none on which container a pseudo-element queries.
- Flexbox and Grid traps: flex: 1 means 1 1 0%, flex: auto means 1 1 auto, flex: none means 0 0 auto and flex: initial means 0 1 auto; flex items do not shrink below their min-content size until min-width (or min-height) is set to 0; justify-content works on the main axis, which is vertical with flex-direction: column; align-content has no effect when flex-wrap is nowrap (state it that way, not as "a single line", because the Flexbox spec says a wrapping container with one line still counts as multi-line); write no card on the initial keyword of justify-content (the specification's normal behaves as flex-start in Flexbox). auto-fit collapses empty repeated tracks while auto-fill keeps them; auto-fill and auto-fit accept only fixed sizes (MDN's <fixed-size>); a subgridded dimension has no implicit tracks; negative line numbers count from the end of the explicit grid only. order and grid-auto-flow: dense change the visual order, not the DOM order; their accessibility consequences belong to web-accessibility.
- Units traps: em inside font-size refers to the inherited (parent's) font-size, elsewhere to the element's own; rem refers to the root element; relative units inside media queries use the initial value of font-size, not the page's styles (cite https://www.w3.org/TR/mediaqueries-4/); children inherit the computed length of an em-based line-height but the factor of a unitless one; container query units fall back to small viewport units when no eligible container exists. The length page says vh and the other unprefixed viewport units are equivalent to the large (lv*) units, and css-values-4 (12 March 2024) pins that mapping as "presumed to be required for Web compatibility" after earlier drafts let browsers choose: at most one card on it, citing the length page, with "may_change". Write no card on how scrollbars affect vw or vh, on device pixel ratios, or on physical accuracy of in, cm or pt on screens. In calc(), + and - need whitespace on both sides (cite the calc-sum page), * and / do not, and `calc(0 + 20px)` is invalid because 0 is a number.
- Custom property traps: var() substitutes tokens, so `var(--n)px` never forms a length; an unregistered custom property inherits and accepts almost any value, and a declaration that becomes invalid at computed-value time behaves as unset (inherited or initial) rather than falling back to an earlier valid declaration; var() cannot appear in media or container query conditions, selectors or property names; @property requires syntax and inherits, and initial-value unless the syntax is "*". A registered property given a value that does not match its syntax does not fall back to an earlier declaration: it takes the inherited value when inherits is true and its initial-value otherwise (the Registering_properties guide's example shows both; its sentence "fall back to its registered default" alone is incomplete, so state the inherits condition). With a non-universal syntax and an initial-value, var() never uses its fallback for that property (var page). Write no card on registering the same property both in CSS and with CSS.registerProperty() beyond the MDN rule that the JavaScript registration wins, and no card on boolean style() queries without a value (their result depends on registration); style query cards use style(--name: value), and MDN says equivalent values such as blue and #0000ff match only when the property is registered with a matching syntax.
- Color traps: oklch() hue angles are not hsl() hue angles; a chroma percentage of 100% is 0.4; a relative color's channel keywords resolve to plain numbers, so calc(l + 0.1) not calc(l + 10%) (MDN notes that Safari's first implementation followed an older draft with units, so older articles may be wrong); light-dark() returns its first value unless the used color scheme is dark, and MDN says color-scheme must allow light dark; color-mix() cards always name the interpolation space and mix exactly two colors, because the MDN page now also shows the newer forms (color space omitted with oklab as default, one color, more than two colors): no card on those forms; write no card on light-dark() with images (a newer extension). Write no card on gamut mapping results, on exact converted channel values, or on which color space looks best, and no colour contrast cards (web-accessibility owns them).
- Motion traps: the first time value in the transition and animation shorthands is the duration and the second the delay; transitions do not run on first render or when display changes from none, which is what @starting-style addresses, and @starting-style must come after the rule it overrides or be nested in it, because it has the same specificity; @starting-style is for transitions only, animations do not need it; allow-discrete flips display at 0% when entering and at 100% when leaving; !important inside @keyframes is ignored; when several @keyframes rules share a name the last one wins, but cascade layers change which one wins, so no such card involves layers. Leave out prefers-reduced-motion (web-accessibility owns it), the Web Animations API, animation-composition, animation-timeline and transitionend event details beyond MDN's statement that it does not fire for a transition aborted before completion.
- Never state a judgement as a fact. "Best practice" or "recommended" is allowed only when the source says it in those terms: MDN advises importing third-party styles into a layer rather than overriding them with !important, MDN calls unitless numbers the preferred way to set line-height, MDN recommends whitespace around * and / for consistency. No cards on naming conventions (BEM), resets, design systems or which layout method is better.
- No trivia: no vendor prefixes, no browser version numbers, no CSSOM API details beyond CSS.registerProperty(), no counts of properties, keywords or CSS-wide keywords, no exact default values that a user agent chooses (the normal line-height, default font sizes), no numeric values of named colors, no history of CSS levels. Leave out print and paged media, @font-face and font loading, @counter-style, @namespace, @page, @supports beyond its use with @import, multi-column layout beyond creating a block formatting context, tables, floats beyond formatting contexts and margin collapsing, the column combinator, shapes, masking, filters beyond creating a stacking context, scroll snap, and the top layer (popover, dialog).
- Overlap with other decks: web-performance (CWV) owns render-blocking CSS, the critical rendering path and the render tree (including display: none and the render tree), content-visibility, will-change as an optimisation, layout shifts (including aspect-ratio and width and height attributes as CLS fixes), font-display and transform animations as a performance topic; here aspect-ratio, will-change and transform appear only for sizing, stacking and containing-block behaviour, and display: none only for layout. web-accessibility (ACC) owns prefers-reduced-motion, :focus-visible, colour contrast, focus outlines, hiding content from assistive technology and the gap between visual order (order, dense packing, positioning) and DOM order. web-security (WEB) owns CSP and style-src. react-fundamentals (RCT) and nextjs-rendering (RND) own className, inline style objects, CSS Modules and framework styling. javascript-fundamentals (JSC) and typescript-fundamentals (TSC) own the DOM and JavaScript. http-fundamentals (HTP) owns HTTP headers and content types. git-fundamentals (GIT), linux-command-line (LNX), docker-fundamentals (DKR), kubernetes-kcna (KCN), kubernetes-ckad (CKD), terraform-associate (TFA), github-actions (GHA), python-fundamentals (PYT), nodejs-fundamentals (NOD), sql-fundamentals (SQL), the cloud decks (CLF, SAA, DVA, CDL, ACE, AZ9, 104) and the other new decks (aws-aif-c01, gcp-pca, azure-az-204, kubernetes-cka, ansible-fundamentals, go-fundamentals, java-fundamentals, graphql-fundamentals) do not overlap.
