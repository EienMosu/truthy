Security: securityContext at Pod level versus container level, where container values take precedence over the same Pod-level fields; runAsUser, runAsGroup, fsGroup and fsGroupChangePolicy; runAsNonRoot making the kubelet refuse to start a container that would run as UID 0; readOnlyRootFilesystem; allowPrivilegeEscalation (true when unset) and why it cannot be false together with privileged or CAP_SYS_ADMIN; privileged; capabilities, privileged, readOnlyRootFilesystem and allowPrivilegeEscalation exist only in the container securityContext (pod-v1 API reference); seccompProfile RuntimeDefault; user namespaces with hostUsers false (stable since v1.36; they need kernel and runtime support, so name it). What seccomp profile applies when none is set depends on the kubelet's seccompDefault setting: write no card on it. KCNA owns the Pod Security Standards levels and Pod Security Admission. Here, a card may say which securityContext setting a Restricted namespace requires, and only if the pod-security-standards page states it.
- Scope of 5.1 NetworkPolicies: Pods are non-isolated by default; a Pod becomes isolated for ingress or egress when any policy that selects it has that policy type; policies are additive allow-lists with no deny rules and never conflict; for a connection between two Pods, both the egress policy of the source and the ingress policy of the destination must allow it; an empty podSelector selects every Pod in the policy's namespace; policyTypes default to Ingress, and Egress is added when the policy has egress rules; namespaceSelector and podSelector in one from element (AND) versus in two elements (OR); ipBlock, and port ranges with endPort (stable since v1.25); traffic to and from the Pod's own node is always allowed; a default-deny egress policy also blocks DNS unless DNS is allowed. KCNA owns the fact that NetworkPolicy needs a network plugin that enforces it. Leave out AdminNetworkPolicy, the network-policy-api project and plugin-specific CRDs (Calico, Cilium).
- Scope of 5.2 Services: the selector matching Pod labels, and an empty EndpointSlice when nothing matches or no Pod is ready; port versus targetPort versus nodePort; a targetPort given by name; a Service without a selector plus manually managed EndpointSlices; headless Services and their DNS records; the DNS name <service>.<namespace>.svc under the cluster domain, and short names resolving only within the Pod's own namespace; Service environment variables, set only for Services in the same namespace that existed before the Pod; kubectl expose and kubectl port-forward; the troubleshooting steps on debug-service. Write no card on the format of Service names (validation was relaxed to RFC 1123 labels, stable in v1.37). KCNA owns the definitions of the Service types.
- Scope of 5.3 Ingress: it needs an Ingress controller; IngressClass and the default IngressClass; host and path rules; pathType Exact, Prefix or ImplementationSpecific and how Prefix matches path elements; defaultBackend for requests that match no rule; TLS from a Secret; Ingress exposes only HTTP and HTTPS, so other protocols use a NodePort or LoadBalancer Service; the Ingress API is GA and frozen, and the Kubernetes project recommends Gateway instead. Popular CKAD material relies on ingress-nginx annotations (such as rewrite-target): annotations are controller-specific, so write no card about any annotation. KCNA owns the Ingress versus Gateway API comparison. Gateway API is not in the CKAD curriculum: no Gateway API cards.
- Version pinning: pin Kubernetes v1.37. When a behaviour changed in a recent release, the statement says so (for example "Since Kubernetes v1.36, ...") and "appliesTo" carries it. Stable features verified on kubernetes.io on 2026-10-08 and testable as current: sidecar containers (v1.33); backoffLimitPerIndex (v1.33); in-place Pod resize and Job managedBy (v1.35); image volumes, user namespaces and MutatingAdmissionPolicy (v1.36); ValidatingAdmissionPolicy (v1.30); CRD validation rules (v1.29); podFailurePolicy (v1.31); the metrics.k8s.io v1 API (v1.37).

Beta or alpha in v1.37 and making common claims arguable: per-container restartPolicy and restartPolicyRules for regular and init containers (ContainerRestartRules, beta since v1.35): write no card that restartPolicy can be set only for the whole Pod or only on init containers; RestartAllContainers (beta since v1.36); the configurable CrashLoopBackOff maximum delay (beta since v1.35); StatefulSet maxUnavailable (beta since v1.35, disabled by default in v1.36 after a bug, enabled again in v1.37); the StatefulSet Recreate update strategy (alpha since v1.37): write no card that StatefulSets cannot use Recreate; mutable scheduling directives and resources for suspended Jobs (beta since v1.36); kubelet image pull credential verification (beta since v1.35); Pod-level resources (beta since v1.34) and their in-place resize (beta since v1.36); Memory QoS (beta, enabled by default in v1.37); HorizontalPodAutoscaler scale to zero (beta, enabled by default in v1.37); in-place resize of memory-backed emptyDir volumes (alpha since v1.37); h2c and gRPC TLS probes (alpha since v1.37); split log streams (alpha).
