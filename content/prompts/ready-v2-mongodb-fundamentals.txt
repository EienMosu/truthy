DECK
MongoDB fundamentals for working developers: the document model, MongoDB Query Language, indexing, schema design and distributed data guarantees.
Taxonomy: backend > MongoDB > topics > Fundamentals. This is a documentation deck, not an exam deck. The source of truth is the official MongoDB documentation.
Pinned to MongoDB Server 9.0, the current stable 9.0-series verified on 2026-10-08. The default context is self-managed MongoDB with ordinary collections; topology-dependent statements identify the deployment. Atlas Infinite and managed-service administration are outside this deck.

- BSON and identity: distinguish stored BSON types from JavaScript values and plain JSON. Date and Timestamp have different roles; ObjectId ordering is approximate rather than a guaranteed insertion order. Do not infer a stored numeric BSON type from a bare JavaScript literal. _id generation may occur in the client or, if omitted in a received document, in mongod; it is not a server-only operation. Scope _id uniqueness to ordinary unsharded collections until r16 introduces the sharded exception (https://www.mongodb.com/docs/manual/reference/bson-types/, https://www.mongodb.com/docs/manual/reference/method/objectid/ and https://www.mongodb.com/docs/manual/core/document/).
- Query and projection context: say whether an operator is a query predicate, projection operator, update operator, aggregation expression or pipeline stage when names overlap. Scalar null equality also matches missing fields; $exists: true includes a present null field. The MongoDB 8.0 null-equality change concerns legacy BSON undefined, not missing fields; legacy undefined data is outside this deck (https://www.mongodb.com/docs/manual/release-notes/8.0-compatibility/). Find projections accept aggregation expressions, so do not repeat the old claim that computed projection requires aggregate() (https://www.mongodb.com/docs/manual/reference/method/db.collection.find/).
- Collection validation: a validator does not give a collection a uniform schema automatically. Name validationLevel and validationAction when the answer depends on them. MongoDB 9.0 adds constraint validation, which checks existing documents when enabled; strict alone does not retroactively validate existing data. Avoid the outdated fixed list of only strict and moderate levels (https://www.mongodb.com/docs/manual/core/schema-validation/specify-validation-level/).
- Updates and pipelines: distinguish replacing a document from changing selected fields, and distinguish $set as an update operator from $set as a stage. r6 tests pipeline updates through their permitted stage subset, not every aggregation stage. Ordered insertMany error handling does not make the batch one atomic transaction. Aggregation output changes stored collections only through writing stages such as $out or $merge (https://www.mongodb.com/docs/manual/reference/method/db.collection.insertmany/, https://www.mongodb.com/docs/manual/tutorial/update-documents-with-aggregation-pipeline/ and https://www.mongodb.com/docs/manual/core/aggregation-pipeline/).
- Current aggregation traps: MongoDB 9.0 adds a per-operation memory limit separate from per-stage limits and disk-spill behavior; allowDiskUse does not mean unlimited operation memory (https://www.mongodb.com/docs/manual/core/aggregation-pipeline-limits/). MongoDB 9.0 reverses the 8.0 deprecation of $where, $function and $accumulator through a WebAssembly-based engine; server-side JavaScript remains outside this deck, but no card may claim those functions are still deprecated (https://www.mongodb.com/docs/manual/core/server-side-javascript/).
- Index reasoning: ESR is a guideline, not a universal optimal order; highly selective ranges can justify ERS. Index eligibility does not guarantee the optimizer chooses an index. Do not test the changing numeric $in threshold for sort behavior (https://www.mongodb.com/docs/manual/tutorial/equality-sort-range-guideline/). Partial unique constraints apply to the indexed subset, and TTL removes expired documents in background work rather than at an exact deadline (https://www.mongodb.com/docs/manual/core/index-partial/ and https://www.mongodb.com/docs/manual/core/index-ttl/).
- Multikey and text scope: a compound multikey index restricts indexed array fields per document, not the number of array-valued fields in the entire collection. In MongoDB 9.0 a concurrent write that makes an indexed field multikey can cause a referencing query to fail with QueryKilledError (https://www.mongodb.com/docs/manual/core/indexes/index-types/index-multikey/ and https://www.mongodb.com/docs/manual/release-notes/9.0-compatibility/). Text indexes and $text are distinct from MongoDB Search indexes; text indexes are not marked deprecated. Search and Vector Search are outside scope, and old Atlas-only Search claims are unsafe because current docs describe self-managed Search (https://www.mongodb.com/docs/manual/core/indexes/index-types/index-text/ and https://www.mongodb.com/docs/search/self-managed/current/deployment/compatibility-requirements/).
- Schema design: embedding and referencing are workload-dependent choices, not universal rankings. Test bounded growth, independent update/read patterns, duplication costs and the behavior of the named documented patterns. The Computed pattern stores derived data and can return stale values when refreshed periodically; it is not merely an aggregation calculation. The Bucket pattern is an application schema pattern here, not a card about internal time series storage (https://www.mongodb.com/docs/manual/data-modeling/best-practices/ and the r12 pattern pages).
- Transactions: distinguish standalone deployments from replica sets and sharded clusters, single-document atomicity from multi-document atomicity, and transaction-level concerns from per-operation concerns. Avoid blanket claims that transactions prohibit collection creation or have a total BSON-document-size cap. In 9.0 external-client concurrent multi-document transactions are server-limited; test that scope rather than the parameter's numeric default. Retry scope depends on the error: a transient transaction error and an unknown commit result are different cases (https://www.mongodb.com/docs/manual/core/transactions-production-consideration/, https://www.mongodb.com/docs/manual/reference/parameters/#mongodb-parameter-param.maxConcurrentMultiDocumentTransactions and https://www.mongodb.com/docs/manual/core/transactions-in-applications/).
- Concerns and causal guarantees: read concern controls visibility and isolation; read preference controls routing. Since 8.0 majority write acknowledgment follows durable oplog recording on a majority, while secondaries apply changes asynchronously, so acknowledgment alone does not guarantee an immediate secondary read sees the change. wtimeout does not roll back successful writes, and arbiters can change implicit write-concern defaults. Prefer explicitly configured concerns over default assertions (https://www.mongodb.com/docs/manual/reference/write-concern/). Causal read-your-writes claims require a causally consistent session with majority read and majority write concerns (https://www.mongodb.com/docs/manual/core/causal-consistency-read-write-concerns/).
- Replication and sharding: separate replication from partitioning. Secondary reads can be stale, arbiters vote without storing data, and elections require a voting majority; avoid election-time guarantees (https://www.mongodb.com/docs/manual/replication/ and https://www.mongodb.com/docs/manual/core/replica-set-elections/). Shard-key values can change under documented conditions, refine appends key fields and reshard changes the key; _id remains immutable. Sharded unique-index restrictions and per-shard _id uniqueness belong to r16 (https://www.mongodb.com/docs/manual/core/sharding-shard-key/ and https://www.mongodb.com/docs/manual/core/index-unique/).
- Balancer traps: current balancing considers collection data amounts rather than simply equal chunk counts. Since 6.0.3 legacy automatic chunk splitting has stopped and autosplit toggles have no effect; this does not mean migration never splits ranges. Do not teach immutable shard keys, fixed chunk-size ceilings or config servers that categorically cannot store application data (https://www.mongodb.com/docs/manual/core/sharding-balancer-administration/, https://www.mongodb.com/docs/manual/reference/method/sh.disableautosplit/ and https://www.mongodb.com/docs/manual/sharding/).
