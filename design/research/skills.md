# Summary

- Local skills are web-landing-page biased. Only three things carry over to a mobile card game: anti-slop bans, the "lock one system" rules, and the mobile image-gen skill's consistency rules. Ignore their scroll/bento/hero/GSAP content.
- Best lock-in rule (taste-skill 4.4 + 4.2): SHAPE CONSISTENCY LOCK (one radius scale, documented per component type), COLOR CONSISTENCY LOCK (one accent, used everywhere), one palette per project, page theme lock (light or dark, never mixed). Adopt these as the design-system contract.
- swiftui-design: 8pt grid (4/8/16/24/32/48), 3+ type scales, one "120% signature detail" per screen, 44pt tap targets, semantic colors with defined dark mode, SF Symbols not emoji. Offer 2-3 distinct directions, then LOCK the system after the user picks. Its DesignTokens enum is a ready SwiftUI token skeleton and should mirror the web CSS tokens 1:1.
- taste-skill bans: AI-purple gradients, Inter-as-default, pure-black shadows, hand-rolled SVG icons, emoji (unless playful is requested), duplicate-intent CTAs, "Fraunces/Instrument Serif" defaults, beige+brass premium palette. Requires loading/empty/error states and :active press feedback (scale 0.98 or -1px). These map directly onto a swipe card game's feedback states.
- imagegen-frontend-mobile: best rules for producing 20 directions. Lock an "app design bible" (platform mode, palette, type, radius, icon style, texture, shadow) BEFORE generating; screens must not drift into a different app; fresh renders, not crops; text must never feel small; avoid box-in-box cards, too many pills/badges, fake-chart spam. It has a style-variation engine (theme paradigm x typography x palette logic x texture x signature components) usable as the axis grid for 20 directions. It generates images only.
- design-dna: useful as the format for recording each of the 20 directions as JSON (design_system tokens, design_style, visual_effects). Its measure-colors.mjs / verify.mjs scripts give a deterministic hex check of built output vs the reference. The winning direction should be frozen as one Design DNA JSON.
- minimalist-skill and brutalist-skill are each a complete, mutually exclusive aesthetic (warm monochrome + pastels, radius <=12px; vs. sharp-corner red/black/mono). Usable as two of the 20 directions, not as a system. Both contradict each other on radius, and brutalist is explicitly "pick ONE, never mix".
- Best external find for feel: valdemird.com "Game feel on the web" gives concrete numbers: squash ~420ms with cubic-bezier(0.22,1,0.36,1), spring overshoot cubic-bezier(0.34,1.56,0.64,1), hitstop 60-90ms for wrong answers, shake ~600ms gated to high tiers, 14 particles/burst over 0.55-0.95s, WebAudio pitch +16Hz per streak (cap 24 steps), streak decay 1.6s, prefers-reduced-motion respected. Blog post, no licence; treat as reference only.
- Best external skill repo: gamedev-skills/awesome-gamedev-agent-skills (Apache-2.0, 1.3k stars, validator-checked) has game-ui-ux and game-feel SKILL.md files. Engine-oriented (Godot/Unity/Phaser), so adopt only the feedback-tier and easing ideas, not the tooling.
- ceorkm/mobile-app-ui-design (MIT, 383 stars, only 4 commits): 4 font sizes / 2 weights, 60/30/10 colour, 8pt grid, thumb zone, Peak-End rule, cites Duolingo. Cheap to read, thin, low maturity; steal the rules, do not depend on it.
- Duolingo DESIGN.md (nexu-io/open-design and mirrors) is the closest real reference for gamified learning UI (green #58cc02, 4px bottom-shadow chunky buttons, 16-20px radii, big display numerals for XP/streak). Third-party reverse-engineering, not official; Feather Bold is proprietary. Use as one of the 20 directions, not as the system (brand-derivative risk).
- Reference libraries: Game UI Database (gameuidatabase.com, ~55k screenshots, filterable by genre/colour/layout) and Interface In Game are for mood-boarding only. gameuidatabase returned HTTP 403 to my fetch and Apple HIG "Designing for games" could not be retrieved (page body empty), so neither was verified first-hand. Claude-Code-Game-Studios (MIT, 25.6k stars) is process-heavy (49 agents) and unsuitable here. The mdskills "mobile-games" skill (sickn33, MIT) is platform constraints and monetisation only, not UI/feel.

# Findings: design skills and reusable design resources for "Cloud Cards"

## Part A: Local skills (read in full except where noted)

Note: ~/.claude/plugins/cache/taste-skill/taste-skill/1.0.0/skills/taste-skill/SKILL.md is 1207 lines; I read lines 1-508 (sections 0-5). The rest was not read. Paths in the plugin cache are under `~/.claude/plugins/cache/taste-skill/taste-skill/1.0.0/skills/<name>/SKILL.md`. The impeccable skill was not read or used.

### design-dna (~/.claude/skills/design-dna/SKILL.md)
What it is: a 3-phase workflow (schema, extract from references, generate from JSON) over three dimensions: `design_system` (tokens), `design_style` (qualitative), `visual_effects`.
Applies to us:
- Use its JSON as the canonical record format for each of the 20 directions and, crucially, for the ONE chosen direction. A frozen Design DNA JSON is a single source of truth that the React, SwiftUI and Compose builds can all derive tokens from.
- Rule worth enforcing: "Do not estimate hex values by eye ... perceived colors drift toward familiar palette defaults (often by a ΔE of 10+). When the reference is an image file, measure instead." It ships `scripts/measure-colors.mjs` and `scripts/verify.mjs` (screenshot vs DNA, per-color ΔE and coverage drift, PASS/FAIL). Useful to check the built React UI against the approved mockup, and to stop drift when cloning natively.
- "Every field populated, no empty strings" for the DNA output.
- Caveat: scripts need `npm install` in the skill folder (not done; instruction was not to install). Visual effects dimension (WebGL, shaders) is mostly irrelevant; a card game needs only CSS/SVG/Canvas-2D level effects.

### swiftui-design (~/.claude/skills/swiftui-design/SKILL.md, MIT, author wholiver)
Directly relevant because the SwiftUI clone is planned. Quotable rules:
- Principle 3: "Always present 2-3 distinct design directions, not one 'final answer'... visually distinct, not just color swaps." Workflow Phase 4: "Let User Choose ... After choice, lock in the design system." This matches the user's "decision must be solid" requirement.
- Principle 4: "Never use emoji as icon substitutes in production UI"; "Never use AI-generated SVG clipart"; prefer SF Symbols.
- Principle 5: "Every element must earn its place ... Whitespace is a feature."
- Principle 6 banned list: purple-to-blue gradient backgrounds, emoji as functional icons, rounded cards with left-border accent, centered hero over gradient, Inter/Roboto as display on Apple platforms, neon-on-dark #0D1117, symmetric 3-col grids, AI-drawn SVG illustrations. Do instead: single warm accent on neutral, serif display (New York), restrained density, "One signature detail at 120% effort per screen".
- Tokens: 8pt grid (4, 8, 16, 24, 32, 48), radius 8/12/16, Display 28-34pt, Heading 20-24, Body 15-17, Caption 12-13. "Use 3+ type scales."
- Checklist: min 44x44pt tap targets, dark mode semantic colors defined and tested, no `GeometryReader`/`UIScreen.main.bounds`, 5-Dimension Review >= 7/10.
- Brand protocol: "5 real brand colors, 10 verified design tokens, 2 font families, 8pt spacing grid" as a quality threshold for a brand-spec.md.
- Caveat: its own serif-display and warm-coral default will push every direction toward one look; treat as one school among several. Its references/ files (anti-ai-slop.md, typography-color.md, design-review.md) were not read.

### taste-skill (design-taste-frontend v2) (first 508 lines)
Scope statement: "Landing pages, portfolios, and redesigns. Not dashboards, not data tables, not multi-step product UI." So it is a weak fit for game UI overall; extract only the general rules.
Rules worth enforcing for us:
- 0.B "Design Read" one-liner before generating: "Reading this as: <page kind> for <audience>, with a <vibe> language, leaning toward <design system or aesthetic family>." Good per-direction header for the 20 concepts.
- 1: three dials DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY (1-10). Usable as a numeric descriptor of each direction. "Motion claimed, motion shown": a direction claiming MOTION >4 must actually show motion.
- 4.1 typography: Inter discouraged as default (Geist, Outfit, Cabinet Grotesk, Satoshi instead); body `max-w-[65ch]`; serif "VERY DISCOURAGED AS DEFAULT", Fraunces and Instrument Serif banned as defaults; emphasis within a headline must be italic/bold of the SAME font, never a random second family; italic descender clearance (`leading-[1.1]` min).
- 4.2 colour: max 1 accent, saturation < 80%; "THE LILA RULE" (no AI purple glow unless brand demands it); "COLOR CONSISTENCY LOCK (mandatory)": once an accent is chosen it is used everywhere; "One palette per project"; premium-consumer palette ban (beige/cream + brass/clay/oxblood + espresso; specific banned hexes such as #f5f1ea, #b08947, #1a1714).
- 4.4: "SHAPE CONSISTENCY LOCK (mandatory): Pick ONE corner-radius scale ... all-sharp, all-soft (12-16px), all-pill ... Mixed systems are allowed only when there is a documented rule (buttons are full-pill, cards are 16px, inputs are 8px)". Cards only when elevation communicates hierarchy; tint shadows to background hue, no pure-black drop shadows.
- 4.5: always implement loading (skeletons matching final layout), empty, error states; tactile `:active` (`-translate-y-[1px]` or `scale-[0.98]`); button contrast WCAG AA (4.5:1 body, 3:1 large); no duplicate CTA intent.
- 4.11 "Page Theme Lock": one theme; sections do not invert.
- 3.C icons: one family per project, one stroke width; never hand-roll SVG icons; Phosphor first. 3.E: never `h-screen`, use `min-h-[100dvh]` (iOS Safari). 3.B: never drive continuous pointer values with `useState`; use Motion `useMotionValue`/`useTransform` (directly relevant to swipe-drag card physics). 3.A: Motion (`motion/react`) for animation; Tailwind v4; self-host fonts with `font-display: swap`.
- 2.A: "One system per project. Do not mix Fluent React with Carbon"; "if the brief reads as one of the systems above, install and use the official package." Material 3 (`@material/web`) and Radix are listed; nothing game-specific. 2.B: Apple Liquid Glass "There is no official liquid-glass.css" so web versions are approximations (and `prefers-reduced-transparency` fallback needed).
- Not applicable: hero rules, eyebrow limits, bento, marquee, GSAP sticky-stack, logo walls, testimonials. Copy rules that do apply: "COPY SELF-AUDIT", no fake-precise numbers, one copy register. Relevant to card explanations: "AI-generated cute copy is worse than boring copy."

### soft-skill (high-end-visual-design) (full)
Web agency look. Mostly web-only, several items conflict with mobile game needs, but some transfer:
- Applicable: "Double-Bezel" nested shell + core with concentric radii (`calc(outer - padding)`), useful for a physical-card look; custom cubic-bezier (`0.32,0.72,0,1`) instead of linear/ease-in-out; animate only `transform` and `opacity`; `backdrop-blur` only on fixed/sticky elements, never on scrolling content; noise overlays only on fixed `pointer-events-none` layers; z-index discipline; `IntersectionObserver` not scroll listeners; press scale 0.98.
- Conflicts: bans Inter/Roboto/Arial/Helvetica (and "Standard thick-stroked Lucide"); mandates `py-24`..`py-40` section padding, scroll entry animations on everything, floating glass nav pill, which do not suit a full-screen mobile card game. Its "Variance Mandate" (never generate the same look twice) is the opposite of design-system lock; fine for ideation, must be switched off for the chosen direction.

### minimalist-skill (full)
Complete aesthetic: warm monochrome (#F7F6F3/#FBFBFA canvas, #111111 text, never #000), spot pastels with paired text colors (pale red #FDEBEC/#9F2F2D, blue #E1F3FE/#1F6C9F, green #EDF3EC/#346538, yellow #FBF3DB/#956400), 1px #EAEAEA borders, radius 8-12px max (bans `rounded-full` on cards and primary buttons), no gradients, no heavy shadows (< 0.05 opacity), ban on emoji and on copy clichés ("Elevate, Seamless, Unleash, Next-Gen, Game-changer, Delve"). Interesting for correct/wrong semantics: the pastel+paired-dark-text pairs are a ready accessible true/false/feedback palette. Usable as one of the 20 directions ("editorial / Notion-like quiz"). It bans Inter and Lucide/Heroicons, recommends Phosphor Bold/Fill or Radix icons.

### brutalist-skill (full)
Two mutually exclusive modes, "Pick ONE per project": Swiss Industrial Print (light #F4F4F0 / #EAE8E3, ink #050505-#111, single red #E61919 / #FF2A2A) or Tactical Telemetry (dark #0A0A0A/#121212, #EAEAEA, same red, optional single terminal-green #4AF626). Rules: absolute rejection of border-radius, massive tight uppercase grotesk (tracking -0.03 to -0.06em, leading 0.85-0.95, `clamp()`), mono micro-type 10-14px uppercase with 0.05-0.1em tracking, 1px/2px structural borders, `display:grid; gap:1px` hairline trick, ASCII framing `[ ]`, halftone/scanline/noise effects. Gradients, soft shadows and translucency "strictly prohibited". Fit: one strong, distinctive direction (true/false as stark binary, red for wrong); risks: 10px mono text conflicts with mobile legibility demands, high data density; dark mode variant is CRT-themed only. Note it lists Inter Extra Bold as an optional font although other skills ban Inter.

### imagegen-frontend-mobile (full)
Image-generation only, no code. Most relevant skill for the 20-direction phase because it is designed for multi-screen mobile sets. Quotable rules:
- Platform mode first: "iOS-native premium", "Android-native premium" or "cross-platform premium neutral"; "Do not mix iOS and Android patterns carelessly." Since the game will exist on web, SwiftUI and Compose, cross-platform neutral is the honest choice.
- APP DESIGN BIBLE RULE: "lock an internal design bible before continuing": platform mode, device frame style, palette logic, typography mood, type scale rhythm, spacing system, corner radius logic, icon style, illustration/imagery treatment, texture intensity, decorative asset language, navigation model, card and list behavior, button styling, shadow language. "Do not let screen 3, 4, or 5 drift into a different app." Mirrors what the owner wants to freeze.
- MULTI-SCREEN CONSISTENCY: may vary composition/feature emphasis/visual tempo; must not vary "product identity, design system, mockup quality, core spacing logic".
- DO NOT CROP OLD IMAGES: generate fresh standalone renders for detail views for readability.
- Text: "if the text feels small, the design is not finished yet"; "Readable beats clever. Readable beats dense."
- Clean layout: avoid "box-in-box-in-box", "giant nested card stacks", "too many pills", "tiny widgets"; prefer "one strong structural move rather than many small noisy ones". "Not always simple, always clean."
- Safe areas: status bar, home indicator, sheet docking zone, gesture space must be respected; "Mobile images should feel like real app screens, not posters." First-screen cleanliness: one focal point, 1-3 line headline, one next action.
- Anti-AI-tell lists: purple-blue fintech gradients, random glass cards, ambient blobs, oversized radii on everything, cloned onboarding screens, generic Lucide-like icons, fake brand names (Acme, NovaCore, Flowbit, Quantix, VeloPay), copy clichés.
- Style Variation Engine: pick one each from Theme Paradigm (8 options), Typography Character (5), Structure Bias (8), Image Art Direction (8), Texture/Surface (8), Palette Logic (8), exactly 4 Signature Components (list of 18), exactly 2 Decorative Assets, exactly 2 Motion-implied languages. This is a ready-made combinatorial axis set for generating 20 non-overlapping directions. Caveat: its baselines (DESIGN_VARIANCE 8, ART_DIRECTION 9, TEXTURE 7) push toward ornate output; "SPACING_GENEROSITY 9" may fight with a quick-tap game loop; its lists do not include game-specific components (swipe card, streak flame, lives, timer ring).

### Cross-skill conflicts to resolve before the 20 directions
- Inter: banned by soft/minimalist/taste (default), allowed by brutalist and as exception by taste. Decide once; a native clone makes SF Pro / Roboto the system-font fallback anyway.
- Radius: minimalist caps at 12px, brutalist 0, taste says pick one scale and document rules per component type.
- Serif: swiftui-design recommends it, taste-skill discourages it as default.
- Icons: Lucide banned/discouraged in three skills; Phosphor is the recommended cross-platform family (has React, and community SwiftUI/Compose ports exist but are not verified here). SF Symbols are not available on web/Android so a native clone implies icons must come from a cross-platform family or be re-drawn per platform.
- Emoji: banned everywhere except playful contexts (taste-skill 3.D explicit override). A card game is arguably a playful context, but this must be a conscious decision.

## Recommended use for the 20-direction phase
1. Keep the 20 directions as Design DNA JSON records, each with a "Design Read" line and the three dials (taste-skill) plus one pick from each axis of the imagegen-mobile style engine, to force real diversity (not colour swaps).
2. Enforce lock rules only on the chosen one: shape lock, colour lock, one icon family/stroke, one radius scale with per-component table, documented type scale (3+ levels, 8pt grid), 44pt/48dp targets, light+dark semantic tokens.
3. Define feedback tokens (durations, easings, haptics, reduced-motion fallbacks) as part of the system using item 2's numbers, since the core loop is feedback-driven.
4. Include at least one Duolingo-adjacent direction (chunky, mascot, display numerals) and one minimalist and one brutalist direction from the local skills, as they are already fully specified.
5. Decide Inter/emoji/serif/Lucide conflicts once up front; they are the main cross-skill contradictions.
